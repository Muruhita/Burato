# Security Policy

## Supported Versions

Проект **Burato** (Discord-бот FIB Forms) активно поддерживается только в актуальной версии ветки `main`. Более старые коммиты и форки не получают обновлений безопасности.

| Version | Supported          |
| ------- | ------------------ |
| `main` (latest) | :white_check_mark: |
| Любые форки / старые коммиты | :x: |

Мы рекомендуем всегда использовать последнюю версию с ветки `main`.

## Reporting a Vulnerability

Если вы обнаружили уязвимость в Burato — пожалуйста, **не создавайте публичный Issue** и не публикуйте детали эксплойта. Вместо этого свяжитесь с нами приватно.

### Каналы связи

- **Discord (приоритетный):** `@muruh1ta`
- **Email:** `murkilanki@gmail.com`
- **GitHub Security Advisory:** используйте вкладку **Security → Report a vulnerability** в этом репозитории

Предпочтительный способ — **GitHub Security Advisory**. Это позволит обсудить проблему в приватном режиме и подготовить исправление до публичного раскрытия.

### Что указать в отчёте

Чтобы ускорить обработку, приложите:

1. **Краткое описание** уязвимости (одно-два предложения).
2. **Тип уязвимости** — например: SQL-инъекция, XSS, CSRF, SSRF, RCE, IDOR, утечка данных, обход аутентификации, обход авторизации, спам/флуд, DoS.
3. **Затронутые компоненты** — файлы, эндпоинты API, страницы сайта.
4. **Шаги воспроизведения** — по возможности подробно, вплоть до curl-запросов.
5. **Proof of Concept** — код, скриншот или видео.
6. **Потенциальное влияние** — что можно сделать, эксплуатируя уязвимость.
7. **Ваши контакты** — Discord / email для обратной связи.
8. **Публичность** — упомяните, если вы уже раскрывали проблему где-либо.

Если что-то из этого отсутствует — не критично, помогите с тем, что можете.

## Scope

### В рамках политики

Уязвимости в следующих компонентах проекта считаются «в scope»:

- **API-эндпоинты** (`pages/api/**`) — аутентификация, авторизация, валидация входных данных, rate-limiting.
- **Discord OAuth flow** — CSRF, утечка state, обход проверки подписи, JWT-forgery.
- **Аутентификация администраторов** — обход проверки `ADMIN_IDS`, повышение привилегий.
- **Redis-взаимодействие** — инъекции, небезопасная десериализация, утечка ключей.
- **Загрузка файлов** (`/api/upload`) — обход whitelist хостеров, загрузка вредоносного контента.
- **Валидация URL** (`lib/urlValidator`) — обход whitelist, SSRF, XSS через ссылки.
- **Санитайзинг ввода** (`lib/sanitize`) — обход фильтрации HTML/control-символов.
- **Anti-spam / античит** — обход лимитов, подмена идентификаторов.
- **Хранение данных** — утечка персональных данных пользователей, токенов или секретов.
- **Логирование** (`lib/logger`) — утечка чувствительной информации через вебхуки.

### Вне scope

Не рассматриваются как уязвимости:

- Отсутствие HTTPS (решается хостингом Vercel автоматически).
- Социальная инженерия против администраторов фракции.
- DDoS-атаки на инфраструктуру (Upstash / Vercel / Discord).
- Проблемы сторонних сервисов (Discord, Upstash, imgbb, Google Safe Browsing).
- Ошибки в HTML/CSS на уровне, не влияющем на безопасность.
- Недостатки в UI/UX без реального security-импакта.
- Уже известные публичные уязвимости сторонних библиотек — сообщайте напрямую их мейнтейнерам (мы подписываемся на обновления).
- Спам-заявки, не нарушающие rate-limits и не эксплуатирующие другие компоненты.
- Расхождения в отображении данных без возможности их изменения.

## Security Design

MurchikBun следует нескольким базовым принципам безопасности:

- **JWT-аутентификация** с секретом через переменную окружения `JWT_SECRET`, без дефолтных значений.
- **CSRF-защита** OAuth-flow через случайный `state`, сохраняемый в Redis на 10 минут.
- **Whitelist хостеров** для загружаемых изображений и ссылок (см. `lib/urlValidator`).
- **Google Safe Browsing** для проверки внешних ссылок (fail-open, не блокирует работу при недоступности API).
- **Санитайзинг пользовательского ввода** — удаление HTML-тегов, control-символов, экранирование `@everyone` / `@here`.
- **Проверка `ADMIN_IDS`** на каждом админ-эндпоинте, независимо от клиентского UI.
- **Rate-limiting** через Redis с автобаном при превышении лимитов.
- **Логирование подозрительных действий** через Discord-вебхуки (админ-действия, банворды, ошибки).

Все секреты хранятся **только** в переменных окружения Vercel. В репозитории они отсутствуют.

## Bug Bounty

На данный момент **программа вознаграждений отсутствует**. Мы не можем гарантировать денежное вознаграждение за найденные уязвимости.

Однако мы:

- Укажем ваше имя (или ник, по желанию) в разделе благодарностей после исправления.
- Отметим вас в релизных заметках, если уязвимость была критичной.
- Гарантируем, что против исследователя **не будет юридических действий**, если он действовал добросовестно и в рамках данной политики.

## Responsible Disclosure Guidelines

Мы просим исследователей:

- **Не эксплуатировать** уязвимость дольше, чем это необходимо для демонстрации.
- **Не получать доступ** к данным других пользователей и не изменять их.
- **Не нарушать работу** сервиса и не атаковать инфраструктуру (DoS, флуд).
- **Не публиковать** детали до тех пор, пока исправление не будет выпущено (по согласованию с нами).
- **Действовать добросовестно** — цель должна быть улучшение безопасности проекта, а не извлечение выгоды.

Мы гарантируем, что добросовестные исследователи не столкнутся с юридическими претензиями с нашей стороны.
